## Effective finite configuration

The complete primary snapshot is `evidence/config/pickle_pure_python_test/18/config.ini` in this review directory. It selects `system.cpu.branchPred`, finite replay, one thread, one predicting thread, 64 FTQ entries, 64-byte prediction width, GHR970, CAM16, Context4096 total entries (2048 sets, two ways), Slot32, confidence FIFO8 and **four prediction stages**. Relevant ranges are configuration lines 270–310. Hint is applied beginning at stage index2; this must not be confused with a three-stage source configuration. The source loop permits a syntactic `first_hit_stage` range of0–3, but this is only a bound from the four-entry vector; it does not prove that stage3 is distinct from stage2 or that all four late-stage delays are reachable. The source guards unsupported Hint combinations with SMT, PairTAGE and idealTwoTaken (`decoupled_bpred.cc:94–113`).

Commit width is eight **groups** (`config.ini:132`). Although `CROB_instPerGroup` is2 (`:91`), the final `RobCompressPolicy` is `none` (`:111`); `src/cpu/o3/rob.cc:203–207` forces one instruction/group. `src/cpu/o3/rob.cc:429–436` sums at most eight groups, and `src/cpu/o3/commit.cc:1315–1339` limits commit callbacks to that window. Thus at most eight non-return indirect commit callbacks can reach Hint in one CPU cycle. Without the compression-policy evidence, asserting either8 or16 would be unjustified.

Simulator `clock` is333 ticks (`config.ini:81`); it is not an ASIC period or frequency. ASIC node, clock, memory topology, resource budgets and the selected timing profile are unresolved design inputs.

## Launch, S3 availability and same-tick counterexample

`requestNewPrediction` snapshots histories and performs the Hint lookup before invoking original predictors (`decoupled_bpred.cc:553–566`). `complete` runs after original predictors fill all four abstract stages and checks the selected baseline against stage2 (`568–588`). The target is changed only in stages2/3 with the same selected non-return indirect (`589–607`). The final choice is then compared with earlier stages, and the first matching stage determines a syntactic0–3 bubble bound (`695–749`); the frozen source does not prove that all values are reachable or that stage3 differs from stage2. `processNewPrediction` waits for those bubbles and FTQ space before inserting the final block and updating histories (`754–812`). A S3 label alone therefore does not define a fixed two-cycle source latency or a three-cycle physical pipeline.

Concrete launch-version counterexample: entryE has confidence1 after the drain of cycleC. Commit atC queues an older wrong prediction againstE, ready atC+1; queryQ at fetchC samples confidence1 and will be eligible to override. AtC+1 the queued decrement changesE to0. A naive CAM-atC/Context-read-atC+1 retiming samples0 and suppressesQ. Source code uses `query->conf`, soQ remains enabled. This proves that naive retiming differs; it does not prove every finite RTL implementation is impossible. A complete candidate must preserve the correct launch version or establish an equivalent earlier/later interface with accepted contract changes.

The three tables sum to104752 logical bits, excluding all histories, snapshots, query/update queues, retired prefixes, logic and control. No claim of an ASIC area budget or full ownership total follows from that subtotal.

At most64 FTQ resident query references coexist. `finalPred` can hold one query outside the active FTQ set, and eight update records can hold queries after their FTQ entries are removed; multiple references may alias the same object. The additive64+1+8 is a conservative storage-sizing envelope, not a proven simultaneously reachable exact occupancy. Intermediate C++ stack/shared_ptr lifetimes and stale-but-inert references can be discarded in hardware only after semantic liveness analysis. The final `max_inflight` numeric contract must name a specific capacity domain rather than claiming64 for the whole implementation.

Recovery work is finite: ordinary speculation updates at most one selected branch per FTQ insertion (`decoupled_bpred.cc:1607–1612`); trap replay invokes the same production update path at most32 times (`1717–1740`); ordinary squash scans at most32 records and conditionally applies at most one correction (`hint_history.cc:195–205`). Call/return updates may happen together. The full-window path must read the evicted PC contribution; a single finite register/SRAM read latency and port model is required for that path. Snapshot restore and clearing up to64 younger FTQ entries are additional operations, although an RTL pointer reset can replace the host pop loop if the live-set semantics are preserved.

## Measurement, off mode and reset boundaries

`hintHistoryTicks` is not a symbol in the frozen `src`, `configs` or `tests` trees. `setCpu` returns before constructing Hint when mode isoff (`decoupled_bpred.cc:219–227`), and all Hint history updates/snapshots are under `if (hint)` (`553–562,1607–1612,1707–1711,1810–1813`). Finite replay constructs Hint even when statistics collection is inactive; histories and lookup/override behavior continue during warmup.

`measurementActive` is functional: `commit` returns before enqueue while inactive (`hint_indirect.cc:891–893`), and `tick` updates its last-cycle marker but stops before applying queued confidence writes (`1002–1010`). Query lookup and override eligibility do not require active measurement (`713–885`). Thus inactive measurement freezes training, not the predictor's history or predictions. A generic removal of all measurement controls as "stats only" changes trained confidence. The enable can be modeled as a finite externally driven training-enable interface. Its source transitions occur in CPU instruction-phase control (`src/cpu/o3/cpu.cc:1443–1447,1478–1485,1500–1521`) and can occur within a commit batch.

Changing measurement state calls `tick(cycle)` before changing the flag (`hint_indirect.cc:1102–1112`); enabling after a cycle's inactive tick does not retroactively drain that cycle. `resetStats` similarly ticks before zeroing counters and explicitly preserves trained confidence and FIFO (`1122–1140`). It does not touch HintHistory. `finish` disables work without draining (`1252–1272`); the caller's exit callback performs only the normal current-cycle tick before finish (`decoupled_bpred.cc:209–213`). File reads populate a frozen image before runtime; file output is diagnostic and can be excluded from the hardware boundary with an explicit preload and observation policy.

## Review boundary

The source proves finite replay geometry, finite state representations, ordered drop-new training, exact lookup/cancel/history semantics and bounded callback work. It supplies obligations for a candidate; it does not supply a physical memory schedule, pipeline timing, total ownership proof, kmhv2 interface implementation, ASIC reset/load protocol or target technology budgets. Those remain design inputs. The naive delayed-confidence-read counterexample is a demonstrated mismatch for that particular mapping, not a universal impossibility result for finite replay. Ideal mode is excluded from the primary gate and must receive its own finite-resource boundary analysis.
